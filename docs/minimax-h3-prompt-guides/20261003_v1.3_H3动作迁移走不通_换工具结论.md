# H3 动作迁移走不通 · 结论与替代方案

> **前提**：已试两版（v1.1 带自编动作 / v1.2 去掉自编动作 + 加时序锚 + 对齐时长），结果都是模型重编。
> **结论先行**：**这不是提示词问题，是工具选型问题。** H3 的 reference video 是「语义级灵感引导」，不是 pose 级动作驱动。继续调词不会有效果。

---

## 一、为什么判断是能力边界，不是措辞

**① 两版都失败，而两版在「关键变量」上是相反的**

| 版本 | 是否自编动作 | 是否给时序锚 | 结果 |
|---|---|---|---|
| v1.1 | 是（写死了八拍走位） | 无 | 重编 |
| v1.2 | 否（只写"复现"） | 有（`<Video 1> fully_preserved`） | 重编 |

这两个变量是 prompt 层面最核心的两个按钮，**按到两个极端都没用** → 瓶颈在模型侧。

**② 社区口径与官方定位一致**

- 官方文档对 r2va 的描述是 *"Reference character, motion, camera, style, voice, or editing rhythm"* 和 *"keeps the features of the reference subject or asset **consistent**"* —— **没有承诺复刻动作**。
- 官方指南把 `<Video N>` 的用途限定为 *camera movement, cuts, rhythm, or **temporal structure*** —— 是**结构性**引导，不是骨骼驱动。
- 社区实测汇总的原话：**"reference does not mean deterministic reproduction"**；H3「动作理解」强于「细节保持」，**快速动作不可靠**。社群排障表里「动作被忽略」的处置建议恰好就是我们已经在做的（"state exactly what Video 1 contributes"）。

**③ 官方自己把 H3 定位成"结构化场景描述系统"，不是动作迁移器**

它擅长的是：原生音效、口型、多模态混合、单镜头调度。**动作 1:1 复刻不在它的能力清单里。**

---

## 二、5 分钟的决定性实验（做完就不用再猜了）

**去掉换人，只测"能不能原样复刻"。**

- content：只有 `reference_video` = 你的源视频 + 一句话文本
- 文本：`Reproduce the video exactly: the same two performers, the same costumes, the same studio, the same camera. Do not change anything.`
- duration / ratio 设成与源视频完全一致
- **不给任何参考图**

| 结果 | 结论 |
|---|---|
| 连"原样复刻"都做不到 | **能力边界确认** → 放弃在 H3 上调词，走第四节 |
| 能原样复刻，一换人就崩 | 问题在「双人同时替换 + 身份锚」，可试第三节的杠杆 |

这一步做完，方向就定了。**别再盲改 prompt。**

## 三、如果还想在 H3 上再试一次，还剩两个没试过的杠杆

### 杠杆 1：任务类型换成 `[video editing]`

你现在用的是 `[reference generation]`，语义是「素材给我灵感」。

官方对 `video editing` 的定义是：**直接修改一条已有的源视频**。这才是"以源视频为底"的语义。官方还规定这类任务的 summary 必须以固定句开头：

```text
summary:
[video editing + reference generation] The target video is an edited version of <Video 1>.
The two performers in <Video 1> are replaced by <Subject 1> and <Subject 3>. Everything else
in <Video 1> — timeline, choreography, timing, shot size, camera position, camera movement,
and set layout — is preserved unchanged.
```

配套改：`<Video 1>` 的 retention 说明改成"作为被编辑的底片"。

**这是目前唯一还没按过的、语义上最接近"强制跟随"的按钮。**

### 杠杆 2：`<Subject 4>` 改成来源于 `<Video 1>`

你这版又变回「棚景凭空描述、无来源」了。但从源视频看，**粉色棚景、红鼓、黑音箱、墨镜本来就是源视频里的东西** —— 那就别把它写成凭空设定，写成保留项：

```text
<Subject 4> is the studio set in <Video 1> — the hot-pink floor and backdrop, red drum kit,
black guitar amplifiers, microphone stand, and black sunglasses.
```

这样两个好处：① 消除"凭空项"，少一块模型可自由发挥的面积；② 背景不用重建，动作读起来更接近源。**不需要再补一张棚景参考图。**

## 四、真正的解法：Wan2.2-Animate（ComfyUI）

**为什么是它**：它就是为「图片 + 视频 → 换人」造的，而且有两种模式，第一种就是你要的：

| 模式 | 做什么 |
|---|---|
| **Replacement（角色替换）** | **把原视频里的人换成你的角色，保留原背景、光照、色彩、时长、音频、FPS** |
| Animation（动作迁移） | 让静态角色图做出参考视频的动作 |

它是 **pose 级骨骼驱动**（DWPreprocessor 提姿态 + SAM2 分割人物 + 蒙版），所以动作是**跟源的**，不是"重新理解后再生成"。这正是 H3 做不到的那件事。

**落地要点**（ComfyUI 官方模板 `Wan Animate 2.2 Character Replacement`）

- 输入：`Load Image`（你的角色定妆图）+ `Load Video`（源视频）
- 人物抠选：`Points Editor` 打正负点 + SAM2 分割
- **分辨率**：留在 **720p 附近**（如 720×720 / 832×480）；1080p 容易报错；输入图和视频都会被**中心裁切**对齐目标分辨率
- **帧数**：`frame_load_cap` 控制，建议 **77–150 帧**；越低越快越稳
- **FPS**：30 为常规
- **提示词**：只写"在干什么"，例如 `the person is dancing` —— 不要写分镜、不要写六段
- 模型文件（按你本地 ComfyUI Manager 实际命名为准）：`Wan2_2-Animate-14B_fp8_*_scaled_KJ.safetensors`（40 系）或 `Wan2.2-Animate-14B-Q4_0.gguf`（低显存），配 `umt5-xxl-enc-bf16` 文本编码器 + `Wan2_1_VAE_bf16` + relight LoRA
- 节点依赖：`ComfyUI-KJNodes`、`ComfyUI-segment-anything-2`、`comfyui-controlnet-aux`

**你现在本地已经有** `~/ai-creative-platform/docs/minimax-h3-comfyui-workflows/` —— 相关素材可以直接往里放。

**一个现实提醒**：Replacement 模式是**逐帧跟随**，所以转场、快切、剧烈晃动会放大伪影。源视频动作越干净、镜头越稳，效果越好。你这段双人舞（有快速转向和换位）属于中等难度，建议先用 3–5 秒最干净的一段试。

## 五、这版提示词里还剩的两个小问题（顺手说一下）

1. **墨镜又被两个 Subject 抢**：`<Subject 2>` 写了 `prop interaction (including sunglasses)`，`<Subject 4>` 又写 `black sunglasses`。我上一版特意拆开的就是这个 —— 本体归 `<Subject 4>`，正文只写"何时戴上"。
2. **`<Subject 2>` 说"包括墨镜在内的道具交互"** —— 如果墨镜是源视频里的道具，那它属于**视觉内容**，不该塞进"动作"这个 Subject 里。

这两条不是本次失败的原因（前面两版都失败了），但会让本来就弱的动作跟随再掉一点。

## 六、推荐分工

| 需求 | 工具 |
|---|---|
| **严格按参考视频替换人物 / 动作 1:1** | **Wan2.2-Animate（ComfyUI，Replacement 模式）** |
| 原生音效 + 对白 + 口型 + 多镜头调度 | H3 |
| 从文字/图凭空造一场戏 | H3 |
| 长视频拼接 | 分段生成 + 尾帧接力（两者都适用） |

**一句话**：把「跟随」交给 Wan Animate，把「创造」交给 H3。别让 H3 做它没打算做的事。

## 七、执行顺序

1. 跑第二节的最小复现实验（5 分钟）→ 定性
2. 定性为能力边界 → 装 Wan2.2-Animate，拿源视频最干净的 3–5 秒先出一版
3. 同时可以顺手试第三节的 `[video editing]` 杠杆（成本低，只要改 summary 和一行 retention）
4. 两条路各自出片后对比，选优
